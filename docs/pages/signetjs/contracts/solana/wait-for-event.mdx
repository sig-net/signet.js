# waitForEvent

Registers a waiter for a specific event and request ID. The waiter is served by
the shared HTTP RPC poller; calling `waitForEvent` does not open a WebSocket or
start a new polling loop. The higher-level `sign()` method uses this flow
internally. Use `waitForEvent` directly when you submit a request instruction
yourself, such as for cross-contract invocations or bidirectional flows.

## Usage

```ts twoslash
// [!include ~/snippets/code/solana/fee-delegation.ts]
const solanaChainSigContract = chainSigContract

const requestId = '0x...'
const txSignature = 'signatureOfTheSignRequestTransaction'
// ---cut---
import { PublicKey } from '@solana/web3.js'

const controller = new AbortController()

const signature = await solanaChainSigContract.waitForEvent({
  eventName: 'signatureRespondedEvent',
  requestId,
  signer: new PublicKey('ResponderPublicKeyHere'),
  afterSignature: txSignature,
  timeoutMs: 60_000,
  signal: controller.signal,
})
```

```ts twoslash
// result.signature - raw Signature { bigR, s, recoveryId }
```

## Sharing the Poller

Each contract creates a lazy poller when no service is injected. Applications
with concurrent contract instances should create one poller per RPC endpoint and
program, then pass it to each contract:

```ts
const eventPoller = new contracts.solana.SolanaEventPoller({
  connection: provider.connection,
  programId,
})

const contract = new contracts.solana.ChainSignatureContract({
  provider,
  programId,
  eventPoller,
})
```

Listen for one event by registering its event name and request ID on the shared
contract. Register the listener before sending the transaction so the poller can
establish its history boundary first:

```ts
import { PublicKey } from '@solana/web3.js'

const requestId = '0x...'
const controller = new AbortController()

await contract.prepareEventPolling()
const signaturePromise = contract.waitForEvent({
  eventName: 'signatureRespondedEvent',
  requestId,
  signer: new PublicKey('ResponderPublicKeyHere'),
  timeoutMs: 60_000,
  signal: controller.signal,
})

try {
  await sendYourSignRequest()
  const signature = await signaturePromise
  console.log('Signature response:', signature)
} finally {
  controller.abort()
}
```

Call `prepareEventPolling()` before submitting the transaction when possible.
This establishes the initial slot boundary and lets the poller observe events
while the submission is being confirmed. `afterSignature` can seed the initial
history boundary when the poller has not started yet.

Keep the poller alive between request batches and call `eventPoller.close()` when
the application shuts down. `eventPoller.restart()` restarts a failed loop while
preserving its in-memory cursor and pending waiters. Poller state is not durable
across a process restart.

## Parameters

| Parameter         | Type                       | Description                                                                                       |
| ----------------- | -------------------------- | ------------------------------------------------------------------------------------------------- |
| `eventName`       | `ChainSignaturesEventName` | Event to listen for (`signatureRespondedEvent`, `signatureErrorEvent`, or `respondBidirectionalEvent`) |
| `requestId`       | `string`                   | Unique identifier for the signature request                                                      |
| `signer`          | `PublicKey`                | Responder address associated with the event                                                       |
| `afterSignature?` | `string`                   | Transaction signature to use as the initial history cursor                                        |
| `timeoutMs?`      | `number`                   | Timeout in milliseconds (default: 60000)                                                          |
| `signal?`         | `AbortSignal`              | Abort signal for cancellation                                                                    |

`backfillIntervalMs`, `backfillLimit`, and `healthCheckIntervalMs` are retained
for source compatibility and are deprecated. Configure polling on the shared
`SolanaEventPoller` instead.

## Returns

The return type depends on the `eventName`:

| Event Name                  | Return Type                         | Description                                                         |
| --------------------------- | ----------------------------------- | ------------------------------------------------------------------- |
| `signatureRespondedEvent`   | `Promise<RSVSignature>`             | The signature in RSV format                                         |
| `signatureErrorEvent`       | `Promise<SignatureErrorData>`       | Error details from the signing request                              |
| `respondBidirectionalEvent` | `Promise<RespondBidirectionalData>` | Serialized output and raw signature from the bidirectional response |
